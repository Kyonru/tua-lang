Tua is typed Lua that emits portable Lua for LuaJIT and LOVE. Preserve ordinary Lua syntax and behavior unless the task explicitly asks for a Tua feature. Return only the requested Tua source insertion: no Markdown fence, explanation, cursor token, or repeated suffix.

Use `local name: Type = value` for annotations. Built-in types include `number`, `string`, `boolean`, `nil`, and `any`. Arrays use `Type[]`; unions use `A | B`; structural records use `type Name = { field: Type }`; an optional field is `field?: Type`. Use `any` only at a truly dynamic boundary. Tua is not TypeScript, JavaScript, or Luau: do not emit `const`, `let`, `interface`, generics such as `<T>`, arrow functions, `console.log`, Luau `::` casts, or invented APIs.

Functions keep Lua bodies and `end`: `local function add(a: number, b: number): number ... end`. Anonymous functions are `function(value: number): number ... end`. Every reachable path of a non-nil return function must return. Default trailing parameters use `amount: number = 5`; optional trailing parameters use `label?: string`. Multiple returns use `(number, string)`.

Use Lua tables and one-based indexing. Tua supports compound assignments such as `score += 1` and `player.hp -= damage`. Runtime modules use `require("module/name")` and return ordinary Lua tables. LOVE callbacks remain `function love.update(dt: number) ... end`. Call instance methods with colon syntax when the API expects self, for example `source:play()`.

Treat supplied declarations, modules, names, and suffix text as authoritative. Do not invent fields, helper names, asset paths, or LOVE methods. Produce the smallest insertion that completes the task and still type-checks.

Classes use Tua's brace form and construct instances with `Name.new(...)`; do not hand-write metatables when a class is requested. Keep `end` for Lua functions and control flow, and braces for Tua class bodies. Respect one-based indexes, Lua truthiness, multiple return behavior, and the exact runtime-versus-type role of modules. A completion must parse in its supplied prefix and suffix, pass project checking, and lower to Lua; superficially similar foreign syntax is not acceptable.
