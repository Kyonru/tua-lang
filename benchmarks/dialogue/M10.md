# M10 — LÖVE showcase and consuming-game qualification

Beacon Harbor demonstrates one player contract through a conversation panel, NPC
speech bubble and non-pausing radio presenter. The independent announcement player
uses a second audio controller and bounded queue. No new core API or mandatory UI
framework is introduced.

## Run and inspect

```sh
cd examples/dialogue/showcase
../../../target/release/tua build
/Applications/love.app/Contents/MacOS/love build
python3 verify.py --tua ../../../target/release/tua
```

## Consuming-game performance

Apple M3 Max / 64 GiB, JIT disabled, five independent alternating trials. Each
workload warms for 2,000 updates and measures 60,000 updates at 1/60 s. Batch CPU
means use GC running without per-update instrumentation; p95 comes from a separate
timestamped pass. Separate GC-stopped processes measure allocation. No profiler
is active. [Raw trials and summary](M10/consumer-performance.json) retain ranges
and exact runtime/harness identity.

| Workload | Baseline median µs/update | Production median µs/update | Median p95 µs, baseline / production |
| --- | ---: | ---: | ---: |
| idle | 0.135 | 0.118 | 0.125 / 0.125 |
| conversation | 0.925 | 0.927 | 1.000 / 0.958 |
| paired | 0.933 | 0.884 | 1.000 / 1.042 |
| announcements | 1.414 | 1.455 | 1.750 / 1.792 |
| reset | 2.002 | 2.059 | 2.000 / 2.042 |

Allocation and post-disposal retained-growth medians match exactly for every
workload, with queue/outcome parity. This is comparable adapter cost, not a
demonstrated speedup. The fixture runs the emitted game dialogue adapter against
fake graphics resources: no draw/GPU/audio cost, full-game throughput or rendered
FPS is measured. Initial module/fixture setup is excluded. Small absolute costs,
trial variation and timer quantization limit overhead claims. No performance
threshold is asserted.
