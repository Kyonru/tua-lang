# Inspector benchmark — Apple M3 Max, 2026-10-25

Measured after the snapshot-envelope fix in `9a886ab`. The original heavy case
disconnected when a truncated snapshot omitted identity fields; those timings
are invalid for active inspection and are excluded. An earlier overloaded run
(host load around 125) is also excluded.

Three fresh processes per case, 3 s warmup + 8 s measurement each, rotated mode
order. Values below are medians across the three runs. The range is the minimum
and maximum per-run mean, not a confidence interval. No rendering or VS Code
sidebar painting is included. See [methodology](README.md) and [raw measurements](results/2026-10-25-m3-max.json).

## Interpretation

- Snapshot work is periodic. Its tail cost matters more than average cost alone.
- Pausing or disabling an already-instrumented game stops snapshots, but store
  update counters and bounded signal history still run. Restart with inspection
  disabled to remove the shim entirely.
- Retained Lua heap measures reachable Lua allocations after full GC, including
  benchmark timing arrays and formatted result strings. Process RSS
  includes native runtime allocations and is noisier; small RSS differences are
  not reliable measurements of inspector memory.
- The heavy active/no-shim mean ranges overlap. Three runs do not establish a
  statistically precise average overhead; tail costs are the stronger signal.
- These results describe these fixtures on this machine, not a percentage FPS
  loss for the zombie game. Workload mix, source sizes, GC, OS scheduling, and
  editor expansion state can change the cost.
- One-minute host load during the accepted comparison ranged from 3.52 to 7.43
  on 16 logical CPUs. Warnings: 0 runs.
