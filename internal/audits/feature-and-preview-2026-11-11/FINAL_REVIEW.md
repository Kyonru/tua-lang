## Actionable finding

### REV-01 / ED-03: Signal Graph state leaked between projects — confirmed and fixed

The Signal Graph reuses its webview panel (`editors/vscode/src/signals/signal-graph.js:30–55`) and previously restored `vscode.getState().signalGraph` without checking project identity (same file, around line 369). A filter from an earlier project can therefore hide all events in a new project and falsely suggest no events exist.

I added an installed VS Code webview reproduction in `editors/vscode/test/webview/suite.js`: show project `one` with `enemy.hit`, enter filter `enemy`, then replace the graph with project `two` containing `player.hit`. Before the fix, `npm --prefix editors/vscode run test:webviews` failed at the new assertion: expected filter `""`, actual `"enemy"`. The existing four-view refresh test verifies that within-project filtering still persists. The narrow fix scopes saved state to the sorted VS Code workspace-folder URI set and restores it only on a match; the same installed-host suite then passed, including a visible `player.hit` assertion. The lead committed source and test as `69e03d1a`. This reproduces webview behavior with simulated project models in the actual VS Code host; it does not perform an end-to-end workspace-folder switch through the extension command.

### REV-03: imported ECS component lost hover schema in one shape — fixed and independently rechecked

The historical MODULES-02 probe uses a **local world** with a component imported from another module. After `14d9a1a2`, a current real-LSP replay still displayed `any | nil` for `world:get(entity, Imported.Position)`. The committed regression covered an **imported world and imported component** through `Shared.world:get`; it did not prove the local-world/imported-component shape. Commit `82b8674f` adds a semantic receiver fallback in project inference and delegates a local hover to the project snapshot only when its imprecise initializer depends on a required module. Broad deferral experiments were removed before commit. Core and LSP tests include an unrelated `any` hover control. I independently ran `RUST_MIN_STACK=16777216 cargo test -p tua-core absolute_project_imported_ecs_component_retains_payload_schema -- --nocapture` and the corresponding `-p tua-lsp imported_ecs_component_result_hover_keeps_schema_in_project` test: 1/1 passed in each crate. The language agent also reported the rebuilt stdio hover as `{ x: number } | nil`. Final workspace and packaged-server checks remain separate.
