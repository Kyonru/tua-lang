## Reproduction commands

From each listed fixture directory, run the repository's absolute `target/debug/tua check`, then `target/debug/tua build`; use `LUA_PATH='build/?.lua;;' lua -e 'local x=dofile("build/main.lua"); print(x.score,x.x)'` for the two store/ECS fixtures. The state/signal/store fixture prints `11 2 paused`. For clean CI-owned oracles, run `cargo test -p tua-cli --test feature_interactions -- --nocapture` from the repository root. Run `make runtime-test LUA=lua` for the bundled helper suite. On this host, `TUA_TEST_LOVE_RUNTIME=1 TUA_LOVE_BIN=/Applications/love.app/Contents/MacOS/love cargo test -p tua-cli --test love_example -- --nocapture` passed 3/3 outside the restricted sandbox; the same command inside the sandbox failed on graphical launch with empty stderr.

The copied feature build directory had an old `tuasignal.lua` whose manifest ownership was `null`. The current compiler correctly preserves an output of unknown ownership. A clean build emits the current helper; the owned-helper refresh regression added in `4f649212` proves unchanged manifest-owned helpers update, while project overrides and manually edited output remain untouched. Removing an old, unowned helper from the output directory is the safe migration step documented in `docs/cli.md`.
