## Confirmed findings and fixes

- **DOM-01, Medium, confirmed:** A `SignalBus` stored in a table lost the `emit` vararg parameter in its structural method type. Valid `shared.events:emit("move", 1, 5)` failed TL1004, and the imported version failed likewise. The source of the loss was `method_function_type` in `crates/tua-core/src/signal.rs`; it used `FunctionType::new_returns_with_required`, which discarded `TypedFunction.vararg_type`. `efb9ddbb` preserves the vararg and parameter names. The new checker test covers local and imported nested buses, valid and wrong payloads. It failed before the fix and passed afterward; `cargo test -p tua-core signal` passed 31/31.
- **DOM-02, Medium, confirmed:** A previously generated helper could stay stale after the compiler's bundled helper changed, causing runtime failure (the feature tour's old output lacked `SignalBus:declare`). The build returned whenever `tuasignal.lua` already existed. `4f649212` refreshes helpers only while the build manifest confirms unchanged ownership, including the watch path; project-provided and manually modified runtimes remain preserved. New CLI tests cover refresh and override preservation, and all three focused CLI tests passed. An old output whose manifest records no owner remains intentionally preserved; `docs/cli.md` states the migration step. A clean project build emitted the current helper and the cross-file interaction fixture ran successfully.
- **DOM-03 / prior MODULES-02, Medium, confirmed at baseline and fixed in `14d9a1a2`:** `Shared.world:get(entity, Shared.Position)` accepted `position.x = "wrong"` across a required module, while same-file `world:get` reported TL1003. This contradicted `docs/ecs.md`'s imported-component type-flow claim and reproduced the earlier imported ECS schema loss in `features-2026-11-07/modules/REPORT.md` as a checker error, not a separate root-cause finding. New CLI test `imported_ecs_component_get_keeps_its_field_type` failed before and passed after the project-analysis change; core/LSP verification is owned by the language lane.
- **DOM-04 / prior ECS-01, Medium, confirmed at baseline and fixed in `68c13600`:** The old `features-2026-11-07/ecs/missing_get` and `missing_remove` projects initially passed `tua check` and `build`, then emitted Lua crashed indexing an absent component. New CLI regression `ecs_absent_component_results_require_a_nil_guard` failed before and passed after the shared checker change. An independent clean-temp CLI replay now exits 1 for both old fixtures with TL1011: `cannot access field x on union type { x: number } | nil; narrow it`. Guarded controls pass. Final full-gate verification belongs to the lead.
