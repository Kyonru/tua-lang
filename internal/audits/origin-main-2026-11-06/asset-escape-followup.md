# CMP-04 companion: decoded asset identity after insertion

The release replay applied a correctly escaped completion for `assets/player's.png` inside a single-quoted Lua string. The inserted source parsed, but checking still reported TL2004 because asset collection used the raw token payload `assets/player\'s.png` as a filesystem path. Fixing insertion alone therefore did not restore the development workflow.

Asset collection now obtains runtime bytes from the existing Lua string decoder and converts valid UTF-8 into its path string. The decoder was moved unchanged from linter-private implementation to `ast_utils`; the existing duplicate-table-key runtime oracle continues using it. No second ad hoc escape parser was introduced. Decoding handles short-string quoted/backslash escapes, decimal and hexadecimal bytes, escaped line endings, whitespace escapes and long-string initial-line/newline rules already supported by the decoder. Invalid/non-UTF-8 static bytes remain unresolved rather than being guessed. Original AST token spans are unchanged.

Regression `asset::tests::escaped_asset_literals_share_runtime_identity_diagnostics_and_hover` creates actual apostrophe/double-quote PNG filenames and uses escaped quote, decimal, hex and long-bracket source spellings. It checks canonical runtime path, valid status, 32x16 dimensions, checker acceptance, snapshot hover, exact original source span and single-line asset-file rename identity with valid escaped output. The initial version returned an unused local warning, which the checker Result exposed as Err; the fixture now returns the image, so verification does not suppress unrelated diagnostics.

Verification commands and final results are recorded alongside `target/origin-main-audit/escaped-assets.log` and `string-decoder-linter.log`. This is a companion root in CMP-04's insertion/metadata workflow, not a new claim that every Lua string consumer has been migrated. Other domain/module string collectors still using raw token spelling need separate fixtures; multiline asset-file rename support remains its pre-existing limitation.

The same shared decoder now also feeds Sprite descriptor string values. A second actual-file regression checks apostrophe-escaped `spriteSheet.image` through pipeline diagnostics and inspector status/dimensions. The original rename regression also needed the same asset-index initialization as the existing rename tests (`set_source_roots` and `refresh_asset_index_from_disk`); its initial zero-edit result was a fixture setup error, not an additional product defect.

Final focused results after last edits: `RUST_MIN_STACK=16777216 cargo test -p tua-core asset::tests::escaped_ -- --test-threads=1`: **2 passed, 0 failed** (`escaped-assets-final.log`); existing `table_literal_rule_uses_runtime_string_and_signed_number_keys`: **1 passed** (`string-decoder-linter.log`). Earlier broader `escaped_` filter additionally passed the existing escaped-shader test. No broad gate repeated by this lane after completion; lead owns final orchestration.
