# Rooftop Relay — simulated Tua game-development trial

This is an agent-built, two-module platformer, not a human usability study. It exercises typed records, structural parameter compatibility, arrays, indexed iteration, compound assignment, module propagation, LOVE input/drawing and emitted Lua runtime behavior. No assets or third-party dependencies are needed beyond Tua and LOVE.

## Play and reproduce

From the repository root:

```sh
internal/audits/origin-main-2026-11-06/games/platformer/run.sh
# Headless gameplay checks with system Lua:
internal/audits/origin-main-2026-11-06/games/platformer/run.sh smoke
# LOVE LuaJIT gameplay plus 30 real graphics frames:
sh internal/audits/origin-main-2026-11-06/games/platformer/love-smoke.sh
# Actual stdio LSP observations:
node internal/audits/origin-main-2026-11-06/games/platformer/probe.js
```

`run.sh` stages sources under `target/game-platformer/project`, runs `tua check` and `tua build`, then launches LOVE. Set `LOVE_BIN` if necessary. A/D or left/right move, Space/up jumps, R restarts and Escape exits. Cross three gaps to reach the green exit. Falling loses; deaths survive restarts. Generated files are kept out of the audit source directory. Running `tua build` directly beside the supplied `tua.toml` also works, but produces a local `build/` directory.

## Results

- Both source files check and build without diagnostics.
- Real LOVE 11.5/LuaJIT smoke passed landing, jump, falling loss, restart, all three roof transitions and winning. The transition assertions deliberately position the character at each departure edge; this verifies physics feasibility, not a full uninterrupted player-input replay.
- A separate actual LOVE window exercised 30 update/draw frames and exited successfully. This verifies graphics/API execution, not visual polish or human playtesting.
- 100,000 stationary updates took 0.034761 seconds under LOVE LuaJIT in one run; this is a microbenchmark, not a frame-time guarantee. System Lua replay also passed (0.052428 seconds).
- Actual LSP requests returned `number` for imported `world.player.x`, all seven Player members after incomplete `world.player.`, the defining declaration in `world.tua`, LOVE rectangle documentation and both rectangle overloads. Signature help after the second comma selects the y parameter. Diagnostics were empty; formatting returned a document edit (not applied/rechecked by this probe).
- The first imported hover took about 26 ms in this small project; subsequent hover/signature/definition/format requests were under 1 ms in the initial run and incomplete-member completion about 4 ms. The checked-in JSON is the later replay and is authoritative for its individual measurements. These are protocol timings, not full keyboard-to-popup latency or a long-session benchmark.

Exact requests, positions, results and timings are in [lsp-evidence.json](lsp-evidence.json). The scripts used the intermediate binary SHA-256 `f8a80336d0859172bc56ec201ef322c679d600794597d984651f47884970a270`; final lead verification may rebuild and rerun them.

## Findings and development friction

No new confirmed product defect was found in this bounded slice. The core record/module/LOVE workflow was straightforward: typed model code remained ordinary Lua after emission, and editor information agreed with the model annotations. Basic collision, gravity and state transitions required no dynamic casts or `any` workarounds.

Two initial trial mistakes are **not Tua defects**: the CLI takes project context from the working directory rather than a positional path; an output directory outside the project root is intentionally rejected with TL2002. The run script now stages an isolated whole project so the output remains within its root. The first signature probe was one character before the comma; moving to the actual post-comma cursor correctly selected the next parameter.

Possible usability improvement: a `--project` CLI option could reduce directory-changing boilerplate for multi-project workflows, but this is a feature proposal rather than a documented contract failure. This trial does not establish a need for protocols or generics: structural records were sufficient.

## Verification limits

The initial sandboxed LOVE process aborted with exit 134; the same local smoke command outside the sandbox passed. No installed VS Code interaction, gamepad input, audio, assets, native classes, hot reload or long-session editing was exercised here. Rendering was executed but not screenshot-reviewed. This trial used only two small modules; it cannot establish large-game performance.

The LOVE smoke runner loaded emitted `world.lua` with graphics disabled and executed [smoke.lua](smoke.lua). The graphical smoke wrapped the emitted `love.update` to request exit after 30 frames, leaving production game source untouched. The source map files were generated by the build, but error remapping was not separately asserted in this slice.

The separate native runtime replay is preserved in [love-smoke.sh](love-smoke.sh) and [love-smoke.log](love-smoke.log). See [integrated verification](../../VERIFICATION.md) for final rebuilt-server provenance.
