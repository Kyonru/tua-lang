Two Tua 0.7.0 games reveal two defects.

Independent agents built a meteor dodger and an alchemy game to test protocols, generics, cross-file types, generated Lua, and language-server assistance during actual game development. This report separates observed behavior from native LOVE and editor UI limits.

Confirmed findings and fixes

A-01 · Medium · Fixed

Imported generic method as a nested argument

math.floor(box:get()) falsely reported TL1004, “expected 1, found 0,” although box:get() returned number. A file-only checker pass treated an unresolved imported return count as zero and retained that diagnostic after project resolution.

The checker now preserves unknown final-call arity until project analysis. Regressions cover one and two returned values, known-prefix errors, no-return calls, overload ambiguity, and emitted-Lua execution.

Minimal reproduction
L-01 · Medium · Fixed

Colon completion suggested data fields

At selected:, the LSP offered both get and non-callable value. Accepting value would form an invalid colon call. Before-fix protocol response contained both labels; after-fix response contains only get.

Shared completion now filters colon candidates to callable members across typed, project, current-file, and incomplete-source paths. Dot completion still includes fields. Core and LSP regressions protect the distinction.

The two agents simulated development independently; these observations are not a human usability study. Existing worktree edits in crates/tua-cli/tests/cli.rs and the 0.7.0 final audit report were preserved and excluded from these commits.

The smokes stub LOVE functions to inspect Lua-level behavior. The LSP scripts validate protocol responses, not VS Code suggestion-menu rendering, trigger latency, or keyboard behavior. This trial samples two game workflows and does not establish universal language reliability.

Recommended next steps

  1. Keep the two regression tests in the trusted quality gate and verify the final product changes with the full workspace suite.
  2. Run both games in a graphical LOVE environment and confirm frames, controls, and game-over/reset behavior.
  3. Add a concise array-indexing example for input-derived indexes; consider a paired runtime/type-import editor action if more trials show the same friction.
